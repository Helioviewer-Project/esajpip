Prepared Tier-1 cache key reuse: evaluated candidate

Conclusion: key preparation/copy/hash work is reduced, but this benchmark does not establish a meaningful overall decode-time improvement. Full-resolution retained-context timings range from 0.50% less time to 1.24% more time. Keep the source change uncommitted for review; do not characterize it as a demonstrated decode speedup.

Implementation and invariants:
- Cache lookup prepares the exact bounded key once. A miss keeps that key in job-local scratch until successful decode, then insertion uses the prepared bytes/hash.
- Main Tier-1 MQ and HT decoders do not change serialized coding metadata. MQ marker padding is restored by opq_mqc_finish_dec before returning. T2 marks corruption before Tier-1 jobs; store still rechecks corruption after decoding.
- Full key-byte comparison, HT Mb key coverage, cache budget, worker configuration, and slot locking are preserved. Store locks and re-reads its slot, retaining no borrowed entry across decoding.
- No new heap allocation. The 12 KiB key scratch plus metadata now lives across decoding, rather than only during lookup/store. WASM stack/runtime tests and targeted native ASan/UBSan checks pass.

Decode timing method:
- Uninstrumented Release/LTO native libraries built with the same toolchain, floating-point contraction disabled as in the project, 8 workers unchanged. Resident compressed JHV data. Input read/loading, Python hashing and output allocation are outside timers.
- Decode includes output packing and decoder cleanup. Wall and process CPU time are recorded. Forward order baseline/candidate and reverse order candidate/baseline; table entries average the two per-order medians.
- Retained-context: every movie frame, 2 warmup sweeps plus 5 measured sweeps (11 measured for single-frame datasets).
- Cold-first-frame: 5 warmups and 11 measured decodes with a fresh context each time; context construction/destruction are outside timers. Output scratch is shared across those trials to avoid allocating a large Python buffer per trial.
- Full, <=1024 level (when available), coarsest level, and central Callisto crops are included.
- Results describe this native decoder workload on macOS arm64, not whole-application playback or other platforms.
