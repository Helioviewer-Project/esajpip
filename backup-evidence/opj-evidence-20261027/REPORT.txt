Selection and history
---------------------
The reconstructed branch has 15 commits after the requested base. See range-diff.txt.
Retained decoder/pool/coefficient reuse, bounded exact Tier-1 reuse, parallel
conversion, NEON/SIMD, vertical 9/7 strip locality, MQ renormalization/reservoir/
packed-context work, work sharing, fused Gray8 output, and vendor encapsulation.
The wide-row 9/7 chunking was restored after paired eight-worker runs showed a
roughly 4% full-width Callisto gain. The separate wide/short worker-count rule
was left out: its two execution orders did not show a repeatable improvement.
Removed the additional reversible 5/3 strip-copy pass. It was neutral/slower in
the per-commit screen and its small TRACE gains were inconsistent in whole-movie
controls. Removing it costs about 0.5% on the final TRACE full-resolution run.
Removed the undocumented 16-worker expansion. The JHV consumer uses at most eight.
Removed the resolution-major packet early-exit: it accepted malformed issue390.jp2
at coarsest resolution while stock refused it. Header validation now matches stock.
Decoder-owned workspace/cache state and private codec/tile access remain in
vendored OpenJPEG behind the opaque workspace interface. Wide-row/odd-origin tests remain.

Performance method
------------------
The fixed-four-worker native screen evaluates each decoder stage in order, using
first/middle/last real frames, two warmups and seven measured sweeps. The serial
base has no reusable decoder or worker-setting API. Results are in benchmarks/screen
and screen.csv; the SIMD-default decision is measured separately under WASM.
Ablations are recorded in ab-forward/ab-reverse, movie-forward/movie-reverse,
progressive, wavelet-*, schedule-*, and threads-* directories. Their hashes match.
Final native timing uses every frame in each movie. It measures decode plus
delivery into a preallocated output buffer from already resident codestream bytes.
Container opening, presentation metadata, filesystem reads, hashes, and rendering are
outside the timed interval. Codestream-header parsing remains included. The selected
branch and prior optimized branch each
have one warmup and three measured full-movie sweeps in each of two reversed orders.
The much slower serial base has one full-movie sweep in each order, supplemented
by the earlier seven-sweep sampled-frame screen. Raw samples and run medians are
preserved; reported numbers are means of the two per-order medians.
Display-size levels include all resolutions whose two axes are at least 1024,
plus full-width Callisto and full-resolution TRACE. Correctness covers every level.
These are decoder measurements on these files and this host, not application FPS.

Validation cost: retained explicitly
-----------------------------------
Restoring packet-header validation costs up to about 15% relative to the prior
optimized branch at reduced display resolutions. It is a correctness decision,
not a claimed performance improvement.
Callisto needs a separate qualification: 511x12 coarsest crops take about
1.9 ms versus 0.95 ms before (roughly 2x). Full-image decoding at that same
coarsest level takes about 1.94 ms versus 1.03 ms before; the requested base
takes about 4.50 ms. Crop-level timing samples are in regional-performance.json;
all reduced Callisto full-frame levels are in callisto-level-performance.json.
All 18 Callisto crop outputs match the prior optimized branch exactly.
